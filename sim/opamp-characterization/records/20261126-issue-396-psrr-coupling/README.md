# Issue #396 — DC PSRR coupling-path probes and candidate X evaluation

Evidence for issue #396. Baseline: DR-013 DUT (`sha256:e954d17d0856…`, record
`20261114-032827-96d9fbc-288af8`). Probes are **single-corner local `ngspice -b` runs** (two
binding points only, no grid); `run.sh` = unity-buffer PSRR bench of
`sim/opamp-characterization/testbench/psrr_v{dd,ss}.cir` at 0.1 Hz (reproduces the baseline:
63.597 dB FS/125 °C/1.80 V on VDD, 54.901 dB SS/−40 °C/1.62 V on VSS). Variant netlists are
generated by `mk.py` from the DR-013 netlist; `vA…vX3.spice` are kept here. Probe numbers are
screening evidence, not grid results (probe decks use the full `sky130.lib.spice` corner lib).

### Reproduce the two binding-point probes

From the repository root, use Python 3, ngspice and the SKY130A model library.
The candidate grid records identify ngspice 47 and open_pdks
`f6eeac7dad085ffcc829ccfd721f7b4ce39edcf7`. The helpers look for
`sky130A/libs.tech/ngspice/sky130.lib.spice` under `PDK_ROOT` (default
`~/.ciel`). Set `SKY130_LIB` to the library file for a different layout.

```bash
record=sim/opamp-characterization/records/20261126-issue-396-psrr-coupling
work=$(mktemp -d)
python3 "$record/mk.py" "$work/vX.spice" XM3:L=0.6:W=9.27 XM4:L=0.6:W=9.27 XM5:L=0.6:W=3.91
cmp "$work/vX.spice" "$record/vX.spice"
"$record/run.sh" "$work/vX.spice" fs 125 1.80 vdd
"$record/run.sh" "$work/vX.spice" ss -40 1.62 vss
"$record/op.sh"  "$work/vX.spice" ss -40 1.62
```

`o0` is the 0.1 Hz output gain in dB for a unit rail excitation. Negating
it gives PSRR, about 76.67 dB on VDD and 71.92 dB on VSS for X at these
corners. The operating-point probe reports about 3.73 µA for M5 at SS/cold.
The generator reads the archived DR-013 PVT netlist by default. Use
`--baseline PATH` to supply a netlist explicitly, or omit the device edits
to generate the unmodified baseline for the same commands.

## 1. Dominant coupling path (controlled perturbation, one change per variant)

Baseline node gains at 0.1 Hz (dB re 1 V rail ripple): VDD @FS/125/1.80: d1 ≈ 0.00, d2 = +0.21
(1.025x), tail −46.7, out −63.6. VSS @SS/−40/1.62: ibias 0.00 (tracks rail exactly), tail −11.9,
d1 −20.1, d2 −43.5, out −54.9.

| Variant (change from DR-013) | VDD PSRR @FS/125 | VSS PSRR @SS/−40 |
|---|---:|---:|
| baseline | 63.60 | 54.90 |
| A: M3/M4 L 0.3→0.6, W×2 | **95.77** (+32.2) | 61.43 (+6.5) |
| B: M5 L 1.2→2.4, W×2 | — | 47.04 (−7.9) |
| C: M5 L 1.2→0.6, W/2 | — | 63.97 (+9.1) |
| D: M7 L 1.2→2.4, W×2 | — | 54.37 (−0.5) |
| E: M6 L 0.3→0.6, W×2 | — | 54.23 (−0.7) |
| X: A + C | 76.67 | 71.92 |

Reading: on VDD the response is dominated by the M3/M4 mirror's Vds-mismatch (channel-length
modulation at L = 0.3 µm; d2 follows the rail 2.5 % high while d1 follows it exactly); doubling
their L moves PSRR+ by +32 dB. On VSS the first-stage tail/mirror path dominates (tail node moves
−11.9 dB with the rail; M3/M4 L and M5 L both move the result by several dB); the output devices
M6/M7 contribute < 1 dB. **Caveat found later:** M5 at L = 0.6 µm falls in a different
sky130 model bin than the 1.2 µm `MB1` it mirrors, so its current halves (DC `id(M5)` 9.52 µA →
4.79 µA at FS/125; 8.59 → 3.73 µA at SS/−40). Variant C/X's VSS gain is therefore confounded with
a tail-current reduction, not a pure output-impedance effect.

**Device geometry in the screen.** All nine variant netlists retain the DR-013
source/drain areas (`as/ad`), perimeters (`ps/pd`) and resistances in squares
(`nrs/nrd`) when a device width changes. For a single finger the SKY130
symbol computes each area as 0.29 × W, each perimeter as 2 × (W + 0.29)
and each resistance in squares as 0.29 / W, with W in µm. In X, M3/M4
each retain 1.34415 µm² per diffusion at W = 9.27 µm (width-scaled area
2.6883 µm²). M5 retains 2.2678 µm² at W = 3.91 µm (width-scaled area
1.1339 µm²). The archived grids use those fixed parasitics. In a separate
FS / 125 °C / 1.80 V check using the archived AC bench at 100 points/decade,
scaling all six terms on M3/M4/M5 shifted GBW from 11.015 to 11.011 MHz.
The grid used 20 points/decade. Both geometries miss 16 MHz at that corner.

## 4. Recommendation: **reject candidate X as built; §2 PSRR row stays OPEN**

Candidate X reaches ≥ 70 dB DC PSRR on both rails at all 15 points (worst 72.10 / 71.92 dB), but
it opens a new GBW miss (11.02 MHz vs 16 MHz) and worsens the existing slew miss (5.04 vs 20 V/µs).
The output swing falls another 27.6 mV and the nominal thermal floor rises to 44.2 nV/√Hz.
Halving the tail current reduces gm1 and the current available for slewing. The
M3/M4 L change alone (A) is the clean VDD fix (+32 dB, no bias change) but leaves VSS at 61.43 dB
(8.57 dB short) at its binding corner. A single follow-up probe (X3: A + M5 L=0.6, mult 4 to
re-center the tail current at 7.27 µA vs 8.59 µA baseline at SS/−40) gave 66.61 dB VSS (3.4 dB
short) and 96.28 dB VDD — suggesting VSS PSRR trades against tail current in this topology.
X3 is a single-corner probe only; no grid or regression was run on it. The canonical DUT
(`design/netlist/opamp_core.spice`, `opamp_core.sch`) is unchanged. Candidate X's netlist is
retained in `netlist-snapshots/20261126-092206-d98af7bb-376bdc-psrr-noise/opamp_core.spice`.
The 70 dB comparison level was not altered; ratification stays with #282/#287.
